# 特殊情形

## 1. Manual Constant Storage Slot

### 1.1 情形说明

部分 Solidity 合约不会使用普通状态变量声明来保存状态，例如：

```solidity
address private _owner;
```

而是定义一个固定 storage slot 常量，然后在 Yul inline assembly 中通过 `sload` / `sstore` 直接读写该 slot：

```solidity
bytes32 internal constant _OWNER_SLOT =
    0xffffffffffffffffffffffffffffffffffffffffffffffffffffffff74873927;
```

```yul
sload(_OWNER_SLOT)
sstore(_OWNER_SLOT, newOwner)
```

这里 `_OWNER_SLOT` 本身不是普通状态变量，而是状态变量所在的 storage slot 编号。
但从合约语义上看，`sload(_OWNER_SLOT)` / `sstore(_OWNER_SLOT, value)` 仍然是在读取或修改合约状态。

### 1.2 常见使用场景

这种写法常见于：

```text
1. upgradeable contract，避免 storage layout 冲突；
2. library / mixin 风格合约，手动控制状态布局；
3. 高度优化合约，减少 Solidity 自动布局和访问成本；
4. proxy / diamond / EIP-1967 一类固定 slot 存储；
5. Solady 等库中使用的 manual storage layout。
```

### 1.3 示例

Solidity 源码：

```solidity
bytes32 internal constant _OWNER_SLOT =
    0xffffffffffffffffffffffffffffffffffffffffffffffffffffffff74873927;

function owner() public view returns (address result) {
    assembly {
        result := sload(_OWNER_SLOT)
    }
}

function _initializeOwner(address newOwner) internal {
    assembly {
        sstore(_OWNER_SLOT, newOwner)
    }
}
```

对应语义：

```text
_OWNER_SLOT 表示 owner 状态所在的固定 storage slot。
sload(_OWNER_SLOT) 表示读取 owner 状态。
sstore(_OWNER_SLOT, newOwner) 表示更新 owner 状态。
```

但在当前 S-SEIR 阶段，不进行变量名推断，不把 `_OWNER_SLOT` 改写为 `owner`。
变量命名和源码级重写留给后续 Solidity 解混淆阶段。

### 1.4 S-SEIR 记录方式

S-SEIR 中仍然使用 `StateVariableRead` / `StateVariableWrite` 表示这类状态读写。

示例：

```json
{
  "kind": "StateVariableWrite",
  "attrs": {
    "access": "storage[_OWNER_SLOT]",
    "value": "newOwner",
    "slot": "_OWNER_SLOT",
    "slot_constant": "_OWNER_SLOT",
    "slot_value": "0xffffffffffffffffffffffffffffffffffffffffffffffffffffffff74873927",
    "storage_model": "manual_constant_slot",
    "state_access": true,
    "state_mutation": true,
    "mutation_kind": "state_write",
    "variable_name_inferred": false,
    "notes": [
      "constant_storage_slot",
      "manual_storage_layout",
      "writes_contract_state"
    ]
  }
}
```

字段含义：

```text
access:
  当前阶段使用固定 slot 表达状态访问位置。

slot_constant:
  源码中定义的 slot 常量名。

slot_value:
  slot 常量对应的真实值。

storage_model:
  manual_constant_slot 表示这是手动固定 slot 存储模型。

state_mutation:
  true 表示该语句会修改合约状态。

variable_name_inferred:
  false 表示当前阶段没有推断高级变量名。
```

### 1.5 solidity-like 输出

solidity-like 中保留固定 slot 表达，同时标注状态语义：

```solidity
storage[_OWNER_SLOT] = newOwner; /* state write, manual slot */
```

如果写入值包含打包逻辑，则保留原始语义表达：

```solidity
storage[_OWNER_SLOT] = (newOwner | ((newOwner == 0) << 255)); /* state write, manual slot */
```

这里不直接输出：

```solidity
owner = newOwner;
```

原因是当前阶段不进行变量名推断，避免把后续源码恢复阶段的命名判断提前固化。
