## 五类能力与 alias 结论

五类均为“已有可复用基础，但尚有明确缺口”：Feasible Control / Guard、Definition Flow、Value Flow、Sink Dependency、Transition Reconstruction。结构 CFG/Guard、FactSSA/RD、位置/操作数和语义边存在，不等于完整可行性证明、VFG、切片或状态转移重建。

**Alias / Storage Address Equivalence 不足以完整支撑 ERC-20 状态依赖。** 现有恢复层支持精确 storage local、有限 Yul slot/hash/byte/path 模式；final binding 按恢复 access 文本，不提供访问时点 key 等价的完整关系。

四项分析均受影响：

1. persistent Reaching Definitions：同址不同文本可能漏传播，同文本 key 重定义可能误传播。
2. Load/Store Value Flow Graph：缺失或错误的位置关联会破坏状态值来源边。
3. StorageWrite backward slicing：仅回溯已存在的数据边可能遗漏前序同址状态写；path/key/value/control 来源必须分别保留。
4. Multi-Sink persistent-state dependency：普通 operand 边可用，但其状态来源沿用同一断点；影响调用/金额/事件/返回/失败依赖。

最小边界只要求 ERC-20 具名状态、单层/嵌套 mapping 和已恢复 Mixed 路径的 root/path/key-use-site/相关 Guard 证据，以及“可证同址、可证异址、可能重叠、证据不足”的区分；不冻结枚举/API、不求解任意地址算术、不重设计 IR。G1–G8 还覆盖控制、definition/input 来源、切片、外部效果、顺序、提交/回滚与未知状态传播；具体补足方式留给 P0-T3。
