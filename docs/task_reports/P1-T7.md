### Public API and canonical seal

Owner: `scripts/s_seir/s_seir_research_guards.py`. Public functions are `canonical_term`, `seal_guard`, `validate_sealed_guard`, `guard_comparison_projection`, `compare_guards`, `build_module1_result`, `validate_module1_result`, `query_module1_edges`, and `serialize_module1_result`.

Canonical rule: `p1-t7/guard-canonicalization/v1`; projection: `p1-t7/typed-guard-projection/v1`. Seal starts by validating the P1-T6 pre-canonical Guard. It retains the frozen six-field term and six-field Guard payload, including Bool/BV/address type, width, signedness, arithmetic mode, cast, scope, assumptions, source refs and symbol bindings. It sorts unordered source refs, bindings and assumptions. It only orders operands of pure same-type `==`, `!=`, bitwise `& | ^`, wrapping `+ *`, and eager Boolean `&& ||` when neither operand contains CHECKED or SHORT_CIRCUIT semantics. It never reassociates or simplifies. Unknown terms remain unknown. P1-T6's typed operator version stays as the first `normalization_rules` entry.

Sealed Guard schema remains `erc20-research/guard/v1`. Its ID is content-addressed using canonical payload, candidate occurrence, pre-canonical Guard reference and rule version; it is a same-run artifact identity, not cross-sample equivalence. `extensions.precanonical_guard_ref` plus `evidence_refs` preserve lineage. The sealed edge keeps its original candidate ID, endpoints, region, context, feasibility and status; `guard_ref` points to the sealed Guard. An additional canonical-seal EvidenceRecord cites the P1-T6 Guard and feasibility evidence. No candidate occurrence is merged.

### Guard comparison

`compare_guards(left, right, context=None, backend=None)` returns only `EQUIVALENT`, `DIFFERENT`, `UNKNOWN`, `TIMEOUT`, or `UNSUPPORTED`, under `p1-t7/guard-comparison/v1`. Exact canonical typed projections in compatible scope and assumptions use a fast path with a projection digest and evidence refs. Artifact IDs, strings and source refs alone cannot prove equivalence or difference. Different but supported typed expressions use the unchanged P1-T6 `Z3Backend.solve` lowering on Boolean inequality, equivalent to XOR. UNSAT proves equivalence; SAT proves difference. The query retains full typed assertions, SMT-LIB, side conditions, digest, backend/version/options, timeout, scope mapping and assumptions. No feasibility query is issued.

Scope and assumption records must be equal, or the caller must supply both exact sides and evidence refs for an explicit mapping. Cross-sample symbols require an evidenced complete bijection with type agreement. Same-input symbols use their P1-T6 declaration identities. Missing mappings return UNKNOWN. Structural comparisons involving checked or short-circuit evaluation return UNSUPPORTED unless the exact typed projection fast path applies; this avoids dropping differing definedness or evaluation order. Backend UNKNOWN/TIMEOUT/UNSUPPORTED retain their own outcomes and reasons. No solver model or proof certificate is claimed.

### Evaluator and metrics

Owner: `experiments/evaluators/module1.py`; matcher version `p1-t7/semantic-edge-matcher/v1`. Only this evaluator/test layer reads micro expected claims. Production Guard/result code has no evaluator, benchmark-answer or oracle dependency. The evaluator takes a Module1Result and independent expected claims and does not mutate the recovery artifact.

Endpoints use canonical action kind and safe typed operand values, plus function signature/entry kind for ENTRY/EXIT. Raw block ID, source span, candidate ID, semantic ID, untyped storage strings and unknown operands cannot establish a cross-sample match. Such rows remain `NON_EVALUABLE`; duplicate semantically identical endpoint groups without a unique pairing remain `AMBIGUOUS`. Guard is compared separately with `compare_guards`.

For each unique expected FEASIBLE/recovered FEASIBLE endpoint pair, equivalent Guard contributes TP and one Guard equivalent; different Guard contributes FP + FN and one Guard different. Missing expected FEASIBLE contributes FN; extra recovered FEASIBLE contributes FP. UNKNOWN/TIMEOUT/UNSUPPORTED Guard comparisons contribute to explicit non-evaluable counts, not TP/FP/FN. Precision=`TP/(TP+FP)`, recall=`TP/(TP+FN)`, F1 is their harmonic mean (zero when both are zero); undefined denominators serialize as null. Guard equivalence rate=`equivalent/(equivalent+different)`. Fake-edge removal rate=`expected fake matched to rejected/(matched rejected+matched feasible)`; unresolved/missing fake candidates have separate coverage rows and are excluded from that rate's denominator. No unknown or unresolved candidate is discarded from coverage. Every metric is recomputable from per-row contributions. Per-case records include expected refs, recovered refs, comparison/query, reason, status, runtime and config.

The 11 persisted micro cases cover straight line, if/else, join, loop, opaque true/false and fake edges, syntactically different equivalent Guards, genuinely different Guards, UNKNOWN, UNSUPPORTED and mixed flattened scope. Their recovery artifacts are frozen P1-T6 test-layer snapshots; P1-T7 production, evaluator and micro tests consume the snapshots without candidate reconstruction or feasibility reruns. Expected typed expressions are authored from fixture semantics and stored only alongside evaluator cases; they are not copied from recovered Guard expressions. Join/loop StorageWrite action values lack certified layout/value identity, so their endpoints are non-evaluable rather than compared by source strings. The mixed flattened case retains **73 unresolved, 0 feasible, 0 rejected** candidates. All 11 case statuses are PARTIAL because unresolved/non-evaluable coverage is explicit. Aggregated micro rows have 6 TP, 1 FP, 1 FN, 2 fake removals, 6 EQUIVALENT, 1 DIFFERENT, 1 UNKNOWN and 1 UNSUPPORTED Guard comparison; these are micro diagnostics, not formal Experiment 1 claims.

### Known limitations / next boundary

Canonicalization is deliberately shallow; solver comparison covers P1-T6's supported Bool/BV subset and returns UNSUPPORTED for structural checked/short-circuit definedness questions. Scope/assumption or symbol mappings without evidence remain UNKNOWN. Action endpoint matching requires typed semantic values or stronger future layout/value evidence; raw storage strings cannot serve as canonical cross-sample location identity. Current flattened/mixed/contextual P1-T6 scopes remain PARTIAL/UNRESOLVED. These are coverage limits, not permission to reinterpret local SAT or omit candidates.
