## AbstractValue / AbstractState

AbstractValue view：`tag / type / values / arithmetic_modes / source_refs / status`。

- `BOTTOM`：无到达贡献，不能携带 unknown/type 缺失原因。
- `FINITE`：非空、有界 typed 整数集合，数值按数值排序并序列化为十进制字符串；type 为 `{name, bit_width, signed}`；支持显式 uintN/intN（8..256，8 的倍数）。uint/int 缺少 N 不猜宽度。超范围 literal 返回 UNKNOWN，不进行隐式截断。
- `TOP`：已知 type 的任意值；只在有限集合 distinct cardinality **大于** cap 或已知 wrapping/bitwise 运算的 TOP 输入时保守放宽。仍保留 type、arithmetic_modes、SourceRefs；没有异常或 evidence 缺失伪装成 TOP。
- `UNKNOWN`：type 为 null、无 finite values、proof UNKNOWN、completion PARTIAL、带原因/affected SourceRefs/scope 的 diagnostics。缺类型/位宽/符号性、缺 operand/算术语义、unsupported、可能 checked 溢出均显式保留。UNKNOWN 不是成功的 TOP。

`arithmetic_modes` 是当前值推导的模式集合：VALUE（literal/copy、不发生算术）、CHECKED、WRAPPING、BITWISE。VALUE 不表示猜测 checked/unchecked。join 对 alternatives 的 modes 作集合并集；运算结果记录本操作实际模式。数值计算即使用 Python integer 作中间载体，也必须先验证类型范围，再按位宽 modulo/有符号解码或 checked overflow 检查，不能输出无限精度数值作为精确 uint/int 结果。

AbstractState view：`region_ref / domain_ref / reached / values / upstream_status`。
`values` 恰覆盖 region 导出的候选，不纳入业务变量或全局 storage/memory。
`candidate_key(region, candidate)` 使用 `region.id + canonical exported candidate record` 的 digest；read/write evidence、SourceRef、diagnostics 集合排序。没有读取 detector 私有 `_binding_key`，没有使用显示名作单独 key。candidate record 中既有 binding/name 信息仅作为原始证据参与 digest；handle 是输入内 runtime identity，不声称重命名或不同输入间等价。

`make_state(..., reached=True)` 为每个候选生成“尚无 supplied abstract value”的 UNKNOWN；绝不把 P1-T2 candidate 当已求出的常量。`reached=False` 是显式未到达的 bottom state，各值为 BOTTOM；local transfer 对未到达 state 严格保持不变。`state_status` 合并当前值与 upstream status；一次有证据的赋值可覆盖该值原来的未初始化原因，但不能清除 upstream incomplete diagnostics。P1-T4 必须在已确认到达贡献上调用局部 transfer，不能借本 API 推断 reachability。

## Local Transfer / Typed SFIR Adaptation

`local_transfer(state, region, candidate, fact, contract, *, bindings=(), copy_candidate=None, operand_candidates=None)` 只接受 candidate.source_refs 中的同一 semantic_id/origin_id/source_lang/kind occurrence，验证当前 FactSSA/raw write 与 candidate.write_evidence 的局部关联；返回新 state，不修改输入。未关联的外部 fact 抛 ContractValidationError；相关但无法解释的 fact 给带来源的 UNKNOWN，不静默略过。

实际消费两条已有 SFIR 路径：

1. `SlitherFactAdapter` 保存的 `fact.evidence.slither` typed lvalue/rvalue/variable_left/variable_right/rvalues/variable，以及已有 semantic operator/checked。Assignment 支持 typed literal、显式选择且匹配现有 FactSSA read binding 的 candidate copy；Binary 支持 `+ - * & | ^`；Phi 对显式 typed literal alternatives 全部取并集，不选择 feasible predecessor；TypeConversion 只支持 identity，非 identity cast 明确 UNSUPPORTED/UNKNOWN。
2. 主线 `SoliditySemanticLifter.atomic_facts`：Assignment 的已有 `semantic.atomic_operation` + 整数 literal RHS token，可结合调用者提供的现有 `function.fact_ssa.bindings` 显式类型解释。只解码整数 token，不解析复合表达式或 Solidity/Yul 源码；没有 typed operands 的 Binary/Yul/normalized expression 保持 UNKNOWN。

`bindings` 直接传现有 FactSSA bindings，通过 candidate 内已导出的 binding_id 精确取 type；不产生 Definition/Use/RD/VFG。`copy_candidate` 指向已有 region candidate。Binary 的 `operand_candidates={'variable_left': candidate, ...}` 指定已有输入候选；实现仅核对 typed operand.text 对应本 fact 的唯一 read.value/binding_id，以及已提供 candidate state 的 type，不寻找 reaching definition。P1-T4 有责任提供到达本 fact 的 state。

`pure_operation(operator, operands, contract, *, sources, mode=None)` 可直接供 P1-T4 对已选取的局部 typed operands 调用；sources 必须引用现有 SFIR 语义证据，CHECKED/WRAPPING 必须来自该证据，不能由调用者猜测。local_transfer 从严格 bool `checked` 读取模式；位运算模式由支持的 `& | ^` 定义确定。checked overflow（包括有的 alternative overflow）给 UNKNOWN，保留 may-fail 原因；不生成 failure path、SAT/UNSAT 或 Guard。TOP checked 输入也 UNKNOWN。缺 mode、unsupported op、unknown operand 保留 operand 原诊断。UNKNOWN 与 BOTTOM 混合 operand 不丢 UNKNOWN 原因。

## Join / Stabilization / Finiteness

`finite / bottom / unknown / normalize_value / validate_value` 是值构造和规范化 API。
`join_values`：BOTTOM 为单位元；同类型 finite union；size > cap 升 TOP；同类型 TOP 吸收 known finite；UNKNOWN 吸收并保留 diagnostics/evidence/modes 并集；冲突的已知类型转为显式 UNKNOWN。异类型是证据冲突的保守处理，不宣称为跨类型精确 lattice。

`value_leq(a,b,contract)` 采用 normalize 后 `join(a,b)==b`。固定类型的有效域验证幂等、交换、结合、upper-bound 性；小型有限集合穷举验证合并不会排除 concrete alternatives，cap 截止明确。状态 join 按相同 region/config/candidate 集合逐项执行，并要求同一 upstream status。UNKNOWN 与 TOP 不互换。

`normalize_state` 规范化 values、来源/模式/诊断集合；`join_states / stabilized / state_leq` 可直接调用。`stabilized(left,left_context,right,right_context,region,contract)` 基于 canonical 内容和有序 context 历史；`state_leq` 要求 context 相同并检查 state join。证据/诊断也参与 equality，避免状态相同但新 unknown evidence 被提前判稳定；对象地址、dict/list 的偶然顺序无关。此 equality 是分析状态稳定检查，不是 clean/obfuscated 程序语义等价证明。

在固定输入的有限候选、types、SourceRefs、诊断原因、观察 arms 下：每个整数 type 的 concrete universe 有界；finite values 上升至 cap 后只能放宽；evidence/diagnostics 为有限宇宙的幂集；context alphabet 与 k 有限。因此域为有限状态/有限高度。无另外 widening；不包含何时 worklist 调 join、资源预算或 whole-region 收敛算法。P1-T4 不得每轮生成新的 SourceRef/iteration id 破坏固定 evidence universe。

## KSwitchContext

view 为 `{k, elements}`；每个 element 恰为 `{region_ref, dispatcher_ref, arm_ref}`，dispatcher 是 P1-T2 CFG_BLOCK SourceRef，arm 是其 cases 中已观察的 CFG_EDGE SourceRef。`empty_context(contract)` 与 `update_context(context, region, observed_arm_ref, contract)` 验证 supplied region/status/CFG refs 和 observed case membership，再 append，保留末 k 项。

历史次序有语义，不能排序；仅集合/对象字段 canonicalize。k=1 对 A→B→A 保留 A；k=2 保留 B,A；重复超过 k 次更新仍允许，不是 loop unroll/iteration/solver budget。collection reorder 测试包括重新调用真实 P1-T2 detector。target_ref、RETURNS_TO_DISPATCHER 和 case guard 原样仅留于结构证据，context 不携带/产生真实 successor。使用本 API 产生 context；传入 scope/k/field 不一致会显式拒绝，不可自行注入未观察的 arm。

## P1-T2 Intake / Diagnostics

`consume_regions(upstream_result, contract)` 直接读取 result.regions，验证原 `FlattenedRegion`，不修改 payload/identity，不读取或重提取 SemanticAction。使用/保留 dispatcher_ref、region_cfg_refs、control_state_candidates、cases、entries、exits、detection_evidence、envelope status/evidence_refs。检测 evidence 必须能在上游 evidence_records 解析。只有完整 CANDIDATE/PROVEN 且无缺失诊断的 region/candidate 才生成初始 view；失败者放 rejected_region_refs 并保留 affected scope/ref/diagnostics。

结果 metadata 包含 domain_ref、bindings、outcome、rejected_region_refs、status、原 upstream_status/candidate_diagnostics/action_input/upstream_evidence_records。bindings 保存 region/domain 引用、初始 state/context、evidence_refs、原 structural_input；不是 node/context final-state 表，也没有 AbstractPropagation artifact。全局 domain rules 可以定义，即使没有可绑定的 region；不得伪造 per-region state。

- 完整的合法空 regions：`outcome=NO_REGION`，completion COMPLETE，proof UNKNOWN，bindings=[]；仅说明无可消费上游 region，不证明没有 flattening。
- ambiguous/no-exit/multi-entry/insufficient/standalone-Yul 等：`NO_CONSUMABLE_REGION`，PARTIAL，保留诊断，不生成 state。
- 有完整 region，但 result 受 unresolved/unanchored action 输入影响：`BOUND + PARTIAL`，保留原 action_input/provenance；每个 state.upstream_status 同样 PARTIAL，局部已知值不能把整体洗白。
- 接口/schema/config/scope 不一致抛出 ContractValidationError，不 catch 后返回空成功。
