## Scope / Typed Symbolic Semantics

Scope comes only from `edge.evidence_refs[0] → record.result.carrier`, its ordered
CFG block/edge witnesses, branch alternatives, local relations, boundary evidence,
region/context refs and source refs. The carrier must agree with candidate identity
evidence. No function-entry path search, endpoint expansion, transitive candidate,
Def-Use/RD/VFG or independent control graph is constructed.

For each path condition, existing typed `evidence.slither` atomic operations are
resolved through exact FactSSA reads/definitions and owner writes. Definitions must
precede use on this carrier, using SFIR block `semantic_ids` within a block.
Source positions, arbitrary node IDs and semantic-node collection order do not
establish execution order. Source strings only verify a CFG terminator/edge/typed
Condition association; they never become an inferred typed AST.

The six-field typed term uses Bool; signed/unsigned 8–256-bit integer types with
explicit width; and 160-bit address types. Supports equality, signed/unsigned
comparison, `+ - *`, bitwise/logical operators, shifts and BV casts. Casts preserve
source signedness for extension; narrowing extracts bits. `CHECKED` operations add
double-width side conditions; `WRAPPING` operations use fixed-width BV results.
There is no unbounded-integer default. Atomic logical operands are already evaluated;
the adapter constructs EAGER logical terms. The backend also explicitly supports
SHORT_CIRCUIT terms with gated RHS side conditions.

Stable input leaves cite entry declaration and FactSSA definition refs; the symbol
identity is the declaration SourceRef, never its display name. Missing input
declaration, mutable state location treated as a value, effectful result, Phi pairing,
or a definition outside the local evidence closure is explicitly unsupported.
The implemented subset does not yet model environment/old-state read leaves.

`scope.scope_completeness=COMPLETE|PARTIAL` is computed before the main query.
Checks cover carrier/path closure, entry/source prefix, in-block semantics/order,
typed closure, exact cache refs, upstream partial/truncated state and local budgets.
It may be downgraded by an opaque solver-call budget cutoff. Reasons have refs and
are serialized. Only an ENTRY-rooted, closed, supported local carrier currently
proves source/prefix coverage. ACTION-rooted carriers remain local-only; this task
does not discover their entry prefixes. Unmodeled evaluated operations, including
unused checked arithmetic, prevent a COMPLETE conclusion.

Every P1-T4 `node_context_ref` uses the frozen exact query API. Returned entries
are persisted with `INCOMING_BEFORE_NODE_TRANSFER` semantics. Reached UNKNOWN
and missing/unreached entries differ; FIXED_POINT is never feasibility. Known
incoming values are evidence, not automatically predicates: P1-T4 lacks the
per-contribution path/value association needed to bind a mutable cache value to
these symbolic definitions safely. Current contextual scopes therefore remain
PARTIAL. This is an explicit support limit, not silent cache merging or a substitute
propagation engine. RESOURCE_LIMIT preserves emitted candidates and upstream
frontier/accounting; no outside-frontier candidate is invented or rejected.

Every call saves its own SolverEvidence artifact with the frozen required fields.

decimal strings for integer literals/counts. No commutative sorting, logical
normalization, XOR equivalence or cross-sample comparison. Unsupported/NOT_RUN
construction retains typed request/scope reasons with `smt2=null`, explicitly no
executed query. No model/proof certificate is fabricated; field is null and reasons
explain non-retention/proof-disabled outcomes. SMT artifacts permit solver replay.

| SAT + COMPLETE | FEASIBLE under recorded scope/assumptions |

outcome/feasibility. Upstream accounting and unresolved scopes are preserved.

## Opaque Predicates

Each predicate has three distinct calls: `OPAQUE_BASE`, `OPAQUE_POSITIVE`,
`OPAQUE_NEGATIVE`, separate from `FEASIBILITY`. B_P includes only earlier taken
predicates and evaluated-expression definedness, never P's chosen branch.
The latter is lowered via typed `P == P` to collect checked side conditions without
asserting P. B_P must be SAT before considering positive/negative UNSAT results.
SAT/UNSAT pairs produce ALWAYS_TRUE, ALWAYS_FALSE or NON_CONSTANT only in a
complete supported scope. Partial semantic coverage, timeout/unknown/unsupported,
or UNSAT base yields UNKNOWN; base infeasibility is separately retained.
Each subsequent P uses its own prefix. No vacuous constant or contract-wide claim.

`opaque_predicate_result` in each associated SolverEvidence points to the three
`query:<digest>` artifacts, avoiding cyclic IDs. The row/shared EvidenceRecord
also names the three complete SolverEvidence artifact IDs. This permits direct
inspection and replay of all evidence supporting each classification.

## Known Limitations / Explicitly Unfinished

Current COMPLETE feasibility support is intentionally entry-carrier based; flattened,
mixed and ACTION-rooted cases can be consumed but generally stay UNRESOLVED.
String-only Yul predicates/switch guards are unsupported; verified BV wrapping
semantics do not imply full Yul predicate recovery. Known cache states without exact
value/path correspondence are never asserted. Division/remainder/exponentiation,
hashes, arbitrary casts, effectful/environment/old-state results, storage aliases,
Phi alternatives and dynamic iteration identities need further evidence or remain
unsupported. Unsupported expressions do not trigger broader exploration.

Not implemented: Guard canonicalization/equivalence, Module1Result/Evaluation,
P2 dataflow/dependency, M3 order/failure/rollback/STIR. P1-T6 ends here; P1-T7 requires
separate authorization.
