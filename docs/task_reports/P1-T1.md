# P1-T1 — Semantic Action Identification

## Goal

只从现行 `s-seir-semantic-fact-ir/v1` 投影六种冻结 `SemanticAction`，建立可同时供 Module 1 控制恢复与 Module 2 后续 sink/dependency recovery 使用的稳定行为锚点。本 Task 不执行后续控制、依赖、顺序或 STIR 分析。

## Framework Alignment

1. **Module / Experiment**：本 Task 属于 Phase 1 / Module 1 — Core Semantic Control Recovery，是 Experiment 1 的入口工程 artifact owner；本 Task 本身不运行正式实验。
2. **消费的 SFIR 事实**：函数 identity/declaration、`semantic_nodes`、`kind`、`semantic` typed fields、`reads/writes/lvalue/rvalue/condition`、`placement`/Fact CFG anchor、FactSSA 引用、storage/call/event/return/revert semantics、`semantic_provenance`、recovery evidence、replacement/merged source provenance 与 SFIR diagnostics。
3. **稳定输出**：冻结的 `SemanticAction` envelope，必需语义字段为 `kind, semantic_ref, operand_refs, control_anchor, replacement_refs`，并携带 shared `ArtifactEnvelope`、`EvidenceRecord`、`SourceRef`、`AnalysisStatus`、canonical serialization 与结构化 coverage diagnostics。
4. **P1-T2 / P1-T5 / P1-T7 消费方式**：P1-T2 读取 actions 及 `control_anchor` 检测 region；P1-T5 用 action identity 作为候选 semantic-control edge endpoint；P1-T7 封装 actions、feasible/unresolved/rejected control 与 Guard。三者不得重新提取 action。
5. **Module 2 复用方式**：同一 action occurrence 是未来 semantic sink anchor；StorageWrite 的 location/key/update refs、ExternalCall 的 target/arguments/value/result refs、Emit arguments/topics、Return values、Revert failure/condition/payload refs及 provenance 均保留为引用，不在本 Task 求 dependency closure。
6. **明确不负责**：可达性/feasibility、dispatcher/flattened region、k-switch、symbolic execution/SMT、Guard normalization、Def-Use、RD、ValueFlow、storage address equivalence、backward slicing、State/Sink Dependency、SemanticEvent、execution order、commit/rollback 与 STIR。
7. **保持的 global invariants**：只消费 SFIR；不建第二套 source/opcode extractor；一个真实 effect 只进入下游一次；替代表示只作 evidence；不同 occurrence 不按 payload 合并；identity 不依赖遍历/list index/object id/random UUID；unknown/unsupported/unanchored 不静默成功；`control_anchor` 不等于 feasibility/Guard/order proof；solver 恒为 `NOT_RUN`；production 不读取 oracle；冻结接口、enum、schema version 与 Module 边界不变。

## SemanticAction mapping

| SFIR semantic occurrence | SemanticAction | 说明 |
| --- | --- | --- |
| `StateWrite` | `StorageWrite` | 保留 structured location/access/keys/update value |
| `ExternalCall`, `LowLevelCall`, `StaticCall`, `DelegateCall`, `PrecompileCall` | `ExternalCall` | call kind/target/arguments/value/result/selector 按 SFIR 字段保存 |
| `ValueTransferCall` | `EtherTransfer` | 只用于 SFIR 明确的 send/transfer semantic |
| `EventEmit` | `Emit` | event/arguments/topics/indexed values 保存 |
| `Revert` | `Revert` | condition/args/payload/error/selector 保存 |
| `Require`, `Assert`（failure evidence 充分） | `Revert` | synthetic failure projection；保存 source condition 与 failure anchor，不求反条件 |
| `Return` | `Return` | values/value/raw-return expression 保存 |

`StateRead` 明确不进入 action/coverage；它仍保留在 SFIR，后续 M2/M3 可解析 action operand 中引用的 storage source。InternalCall、NewContract、SelfDestruct 等冻结范围外但 effect-like 的节点进入 `UNRESOLVED/UNSUPPORTED` coverage，不扩 action enum。

## Action identity

identity basis 为 `function_ref + semantic occurrence provenance + action kind`。function_ref 带 input fingerprint、contract/declaration、canonical signature、entry kind 与 SFIR locator。occurrence 优先使用 source span、completed overlay id、operation id + statement refs；遍历顺序、list index、Python object id、随机 UUID、FactSSA serial 均不参与稳定 identity。

相同 payload 的不同 span/overlay/operation occurrence 得到不同 id；同一 SFIR 重复运行及 `semantic_nodes` 无意义重排保持相同 fingerprint/id。缺稳定 provenance 时使用 `RUN_LOCAL` scope、semantic locator 仅作冲突区分，并显式 `INSUFFICIENT_EVIDENCE/PARTIAL`，不冒充跨运行稳定。

调用方有正式 compilation input fingerprint 时应通过 `input_fingerprint=` 传入；否则 extractor 使用对已知无序 SFIR collection 排序后的 canonical fallback digest，并在结果记录 `input_fingerprint_source=sfir_canonical_fallback`。

## Operand/effect preservation

每个 operand ref 包含 `role, field_path, source_ref, value`，已有匹配 FactSSA reads/writes 时附 `fact_ssa_refs`；这只是保存 SFIR reference，不追踪 definition。已验证的角色包括：

- StorageWrite：`storage_location`, `storage_keys`, `update_value`；
- ExternalCall：`call_kind`, `target`, `arguments`, `value`, `result`, `selector`；
- EtherTransfer：`target`, `value`, `transfer_method`, `result`；
- Emit：`event`, `event_arguments`, `event_topics`, `event_indexed_values`；
- Return：`return_values`；
- Revert/Require/Assert：`failure_condition_source`, `failure_control_source`, `revert_arguments`, `revert_payload`, `revert_error`。

字段缺失生成 affected-scope diagnostic；只有 SFIR 明确给出空 arguments/values 时才保留真实空集合。

## M1/M2 shared-fact boundary

对 M1，`payload.control_anchor` 只是可解析 `CFG_BLOCK SourceRef`，供 P1-T2/T5/T7 定位 occurrence。unanchored 时 action 仍被保留，anchor 为 structured unknown；没有据此产生 feasibility、Guard、dominance 或 order 结论。

对未来 M2，同一 action 通过 role-addressed operand refs 成为 candidate sink anchor。P1-T1 保存 SFIR 已有的 location/call/event/return/failure facts，但没有 Definition/Use、RD、VFG、slice、StateDependency 或 external-state-impact conclusion。M2 若发现上游 evidence 不足，应新增 diagnostic/refinement evidence，不改写 SemanticAction。

## Replacement / dedup semantics

- 显式 `replaced_by/canonical_semantic_ref` occurrence：coverage=`REPLACED`，只产生 evidence，不产生 action。
- SFIR canonical node 的 `merged_semantic_sources`：canonical occurrence=`EMITTED`；其他 representation 各记一项 `REPLACED` 并进入 `replacement_refs/evidence`。
- Require/Assert 的 `require_failure_cfg_node` 会解析 raw CFG→Fact CFG；若同一 failure occurrence 已有 canonical `Revert`，Require/Assert coverage=`REPLACED`，不会生成第二个 Revert。
- `call{value:x}` 只生成 `ExternalCall`，value 是 operand；只有 `ValueTransferCall` 生成 `EtherTransfer`。

以上去重依据 SFIR replacement/provenance/control occurrence，不按 canonical payload 合并独立副作用。

## Action coverage audit

内部 extraction result 为每个进入范围的 effect-like occurrence记录：

- `EMITTED`：产生一个 effective SemanticAction；
- `REPLACED`：canonical occurrence 已计效，当前 representation 仅作 evidence；
- `UNRESOLVED`：冻结六类无法安全映射，保留 reason/evidence/status。

coverage record 带 deterministic `coverage_id`、occurrence/canonical/action refs、reason、evidence refs 与 status；它是 extractor validation/result，不冻结成新的跨 Task artifact。`FutureEffect` 负例验证无 silent omission。`StateRead` 是明确的 non-action，不被误报为漏项。

## Unknown / unsupported handling

- unknown target/operand：action kind 可证时仍 `EMITTED`，但 action `completion=PARTIAL` 且 diagnostic 指向 operand role；不伪造 `[]`。
- unanchored semantic：action 不丢弃；`control_anchor.state=UNKNOWN`，`INSUFFICIENT_EVIDENCE`。
- insufficient Require/Assert failure evidence：不合成 action，coverage=`UNRESOLVED`。
- unknown effect kind/out-of-scope effect：coverage=`UNRESOLVED/UNSUPPORTED`，不新增 `UnknownAction`。
- standalone Yul object/non-SFIR schema：结构化 `UNSUPPORTED/PARTIAL`；未新增 frontend。
- SFIR 原 diagnostics 保留原记录和 `RECOVERY_DIAGNOSTIC SourceRef`；映射为 frozen diagnostic code。异常不被捕获为空成功。

## Solidity / Yul / Mixed coverage

targeted tests 同时使用 `SemanticFactIRBridge` 的 Solidity/Yul nodes，验证相同 StateWrite 统一为 `StorageWrite` 且保留不同 representation provenance。真实临时 Solidity contract 经 `build_sseir → build_function_level_semantic_fact_ir_payload → extract_semantic_actions` 产生全部六类；inline-Yul/Mixed 继续复用现有 completed overlay→SFIR 边界。独立 Yul object→SFIR 仍未支持，按上游限制返回 UNSUPPORTED，不扩 frontend。

## P1-T2 handoff

- 取得全部 action：调用上述入口，读取 `result["actions"]`；P1-T2 不得重新扫描 semantic nodes 提取 action。
- action id：`action["id"]`；identity 为 provenance occurrence，不用于证明 execution order，也不要求 clean/obfuscated 相同。
- semantic_ref：`action["payload"]["semantic_ref"]`，按 `function_ref + locator.semantic_id` 回到原 SFIR node。
- control_anchor：`action["payload"]["control_anchor"]`；正常为 `CFG_BLOCK SourceRef`，unknown 时含 `state/reason_code/semantic_ref`。
- evidence/status：以 `result["evidence_records"]` 按 id 建索引，解析 `action["evidence_refs"]`；始终检查 action/result `status` 与 diagnostics，solver 在本 Task 必为 `NOT_RUN`。
- replacement_refs：表示已被当前 canonical action 覆盖的 representation，只作 provenance/evidence，不可建立第二个 action/edge endpoint。
- unresolved extraction：读取 `result["coverage"]` 中 `classification == "UNRESOLVED"` 和 `result["unresolved_diagnostics"]`；不得把其当作不存在或 infeasible。
- P1-T2 消费 action 的 `control_anchor` 做 region detection，但不得把 anchor 本身当 feasibility/Guard/order proof。

## Module 2 future-consumer notes
